# 小熊猫摘星星游戏设计文档

一款以太空和月球为背景的浏览器休闲游戏。穿着宇航服的小熊猫从月面起跳，通过连续踩中星星保持腾空并积累分数；音乐扩展让踩星同时成为演奏旋律的过程。

首版建议先验证基础跳跃与一首内置 MIDI 的自由演奏，再开放用户导入 MIDI，最后评估 MP3 和 WAV 音符识别。本文件记录设计，不代表游戏或音乐解析器已经实现。

## 一、已确定的设计

| 项目 | 用户口述设定 |
| --- | --- |
| 玩法来源 | 以"奥比摘星"为复刻参考。 |
| 世界与角色 | 太空、星星、月球表面，主角为穿宇航服的小熊猫。 |
| 启动与运动 | 首次单击鼠标起跳，模拟重力下坠；腾空过程中踩到星星再次向上弹起。 |
| 计分与结束 | 第一颗星星 100 分，之后每颗递增 10 分；落地后结束游戏。 |
| 音乐方向 | 希望上传音乐并解析音符，将音符对应星星，踩中发声；浏览器保留文件或解析结果。先内置一个音乐文件打通流程。 |

## 二、设计状态说明

"已确定"指用户明确提出的要求。"建议"指为了形成可实现方案补充的细节，可继续修改。"待讨论"指存在玩法取舍，尚未作为最终规则。音乐扩展整体仍属待讨论范围。

## 三、参考资料与使用边界

检索到玩家发布的《奥比岛 奥比摘星 塔台》视频条目，以及手游"调皮的星星"宣传条目，后者描述了踏星向上的挑战。[1][2] 本作以用户口述规则为基线，后续如需精确还原，可选定具体原版录像逐项对照。

建议借鉴起跳、踩星连跳和落地结算的玩法结构，角色、月球场景、UI 和声音采用本作自己的设计。本文新增的控制方式和参数均为原型建议。

## 四、核心玩法与单局流程

### 开始与控制（建议）

以下描述自由模式（跳跃摘星）；音乐模式为"引航"形态，控制与节奏规则见第八节。

待机时小熊猫站在月面，显示"单击起跳，移动鼠标接住下一颗星"。第一次点击游戏区域后起跳并启用声音；点击按钮不触发起跳。空中再次点击不增加跳跃次数，持续腾空必须依靠踩星。

横向移动建议跟随鼠标目标位置，但设置最大速度，避免瞬移跨越整个屏幕；左右边界限制角色中心位置，不穿墙。键盘左右键作为备用控制。手机后续可用拖动控制横移、轻触起跳。

### 踩星判定（建议）

在跳起/下降过程中接触到星星就触发踩星。有效踩中一次，立即结算该颗分数，将竖直速度重置为向上的弹跳速度，星星消失并释放粒子。

### 计分规则（已确定并形式化）

第 n 颗星得分为 100 + 10 × (n − 1)。累计 n 颗的总分为 100 × n + 5 × n × (n − 1)。首颗记 n = 1，不额外增加连击倍率或高度加分。

| 踩中颗数 | 本颗分数 | 累计总分 |
| --- | --- | --- |
| 0 | — | 0 |
| 1 | 100 | 100 |
| 2 | 110 | 210 |
| 3 | 120 | 330 |
| 5 | 140 | 600 |
| 10 | 190 | 1450 |

### 落地与重开（建议细化）

初始站立不算失败；首次起跳后，再次接触月面即结束本局，包括一颗星也没踩中的情况。结算显示总分、摘星数、最高纪录，以及音乐模式的演奏进度。点击"再玩一次"回到待机，清空本局数据并重新生成星星。（音乐模式例外：无落地失败，曲终即结算，见第八节。）

状态顺序为待机、游戏中、结算；游戏中可暂停。切到后台自动暂停，恢复时由玩家点击继续，避免后台计时使角色直接落地。

## 五、画面与交互细节

### 整体视觉（建议）

采用温暖、柔和的二维卡通太空风格。深蓝色宇宙衬托亮白色可踩星星，远处行星与细小星点保持低亮度。月面为灰色弧形地平线，搭配陨石坑、轻微尘埃和角色投影，建立明确的落地位置。

小熊猫保留红棕色毛发、白色脸颊、圆耳朵，不需要尾巴。宇航服以米白色为主，蓝色接口作点缀；透明头盔露出面部，尾巴在宇航服内所以不需要显示。

### 屏幕布局（建议）

首版使用固定游戏视口，月面位于画面底部约 15% 区域；星星在上方活动区持续补充。顶部左侧展示当前得分与摘星数，右侧声音按钮和音乐列表按钮，不提供暂停按钮（网页切屏自动暂停）。音乐模式追加曲名及"已演奏音符 / 总音符"，不遮挡落点。

采用无限向上滚屏，视口状态和角色跳跃状态绑定，角色上升视口上升，角色下降视口下降，视口保持角色下落跟踪；阶梯路径生成后即确定，只渲染角色附近的高度区间，未踩到的星星静止留在原高度，回到月面即结束。

### 角色动作与踩星反馈（建议）

| 时刻 | 角色表现 | 画面与声音 |
| --- | --- | --- |
| 月面待机 | 根据鼠标位置只展示侧边，角色水平方向紧紧跟随鼠标，鼠标快速移动时角色稍微带一点延迟后快速移动到鼠标水平位置 | 参考图在 assets 目录下 |
| 首次起跳 | 站立走动状态下直接起跳 | 播放轻柔起跳音 |
| 上升与下降 | 上升伸腿，下降收腿 | 参考图在 assets 目录下 |
| 踩中星星 | 脚部短促压缩后弹起 | 星星位置显示 +100 等分值，星星爆开成环绕一圈的小星星粒子，逐渐消失 |
| 回到月面 | 直接恢复站立 / 走动状态，不做蹲下缓冲动作 | 参考图在 assets 目录下 |

### 星星识别与可访问性（建议）

装饰星点不具备实体轮廓；可踩星星尺寸更大、带清晰边缘与柔和光晕。音乐模式用编号和亮度标示下一颗目标，不能只靠颜色区分。提供静音、音量和减少特效选项，关闭声音不影响计分。

首页保留"开始""玩法说明""音乐选择"三个入口。原型期音乐选择只展示内置曲目；上传功能完成后再出现导入入口，避免按钮指向未实现功能。

## 六、物理与星星生成方案

### 术语约定

- **弹跳速度**：起跳与踩星获得的向上初速度，起跳和踩星共用同一个值，保证手感可预期。
- **月面线**：角色站立与落地判定的水平线，位于画面底部约 15% 处。
- **延迟跟随**：鼠标横向移动后，角色延迟约 0.1 秒才开始追向鼠标位置的控制方式。

### 手感锚点（已确定：轻盈飘浮）

单次跳跃跳高约 220px（画面高度的 40%），滞空约 1.27 秒（M1 试玩后由 0.9 秒上调，增强飘浮感）。由这两个手感锚点反推物理参数：

| 参数 | 数值 | 说明 |
| --- | --- | --- |
| 重力加速度 | 1085 px/s²（M1 试玩定稿） | 低重力漂浮感，呼应月球背景 |
| 弹跳速度 | 690 px/s（M1 试玩定稿） | 起跳与踩星共用 |
| 上升 / 下落耗时 | 各约 0.64 秒 | 顶点附近速度最慢，留出瞄准下一颗星的时间 |

### 横向控制（已确定：延迟跟随）

鼠标横向移动后，角色延迟约 0.1 秒（M1 试玩定稿，由 0.2 秒下调）才开始移动，随后紧贴跟随鼠标的水平位置。

跟随速度上限 1600 px/s（M1 试玩定稿，由 1200 上调），避免远距离时像瞬移；左右边界限制角色中心位置，不穿墙。

### 星星生成（已确定：阶梯式 + 布局预确定）

星星以向上的阶梯（zigzag）形式布局，示意如下（o 为角色，* 为星星）：

```
        *
   *
            *
                        *
            *
       *
o
```

角色踩到星星后向上弹起，整个视口随之上移，更高处的星星进入渲染范围。

阶梯参数（已确定）：

| 参数 | 数值 | 说明 |
| --- | --- | --- |
| 横向步距 | 120–280px 随机 | 太小像走直线，太大跟不上 0.2 秒延迟 |
| 纵向步距 | 100–160px 随机 | 单跳上限 220px 内留足富余 |
| 走向 | 左右随机 | 触及画面边界时折返 |

布局预确定（已确定）：一段阶梯在生成时即完全确定，角色未跳到对应高度只是尚未渲染。实现上采用世界坐标 + 摄像机滚动，视口只绘制角色附近的高度区间。

建议：自由模式按"角色上方约两个画面高度"为最小预生成窗口，随到随铺；音乐模式整首曲子的音符序列有限，开局即可铺完整条阶梯，爬到顶 = 演奏完整首曲子。

### 星星运动与难度（已确定：静止星 + 不加压）

- 星星静止在世界坐标中，不自行下落；画面里的相对运动全部来自角色弹跳和视口滚动。
- 坠落自救（已确定）：下落途中碰到任何未踩的星星，照常弹起、照常计分。已踩过的星星会消失，下方只剩稀疏残阵，自救有难度但不绝望。
- 难度不随时间加压，紧张感只来自分值递增与坠落风险。

### 星星外观与分值（已确定：大小统一）

- 所有可踩星星大小统一，半径约 14px，分值不由大小区分。
- 踩中时在星星位置飘字显示本颗分值（+100、+110……），呼应第四节计分规则。

### 音乐模式引航形态（已确定，M4 试玩后改版）

音乐模式不使用弹跳物理，改用自由漂浮：

- 角色上下左右朝鼠标位置缓慢漂移，按住鼠标明显加速，松开后快速减速回慢速；只保留微弱重力下坠感，不再弹跳。
- 星星横坐标 = 音高：每首歌的最低音贴屏幕左边、最高音贴右边，旋律轮廓直接可见。
- 星星纵向间隔加大且随机（不再由音符时间间隔反推）。
- 引航手感参数（漂移速度、加速力度、减速快慢、微弱重力）待原型试玩后定稿回写本节。

第六节除引航手感参数待原型定稿外，其余全部定案。

## 七、音乐解析与发声的可行性

可以实现，但必须区分"读取乐谱事件"和"从声音猜测音符"。内置七个唱名或十二个半音不能解决录音转谱；音符包含音高与八度、开始时间、时长和力度，音色则由合成器或采样音源决定。

| 输入 | 处理方法 | 建议定位 |
| --- | --- | --- |
| MIDI 文件 | 读取音符事件、轨道及速度变化 | 首版优先，适合准确验证音符顺序 |
| 单乐器或单旋律音频 | 解码后估计音高和音符起止 | 后续实验，需试听和修正 |
| 人声加多乐器歌曲 | 多音转录，可能还需音源分离 | 难度较高，不承诺完整还原 |

### MIDI 路径（推荐）

读取文件，解析轨道和速度表，选择旋律轨，将 tick 时间按速度变化转换为秒，标准化为音符事件，再生成星星路线。@tonejs/midi 已提供浏览器读取 MIDI 以及音高、时间、时长等数据的能力，可作为候选解析库。[3]

首版限定单旋律轨，不包含鼓轨、弯音或踏板等复杂表达。多轨 MIDI 导入时先让用户试听并选择主旋律轨，不默认把所有乐器的所有音符混在一起。相同音高连续出现仍是独立音符，不能简单去重。

### MP3 和 WAV 路径（扩展讨论）

音频解码只是获得波形，之后仍需转录模型或音高与起止检测算法。Spotify Basic Pitch 支持音频转 MIDI 和多音识别，但官方说明它在一次处理一种乐器时效果最好；复杂混音仍需实测。[4]

建议后续先限定短时单乐器素材，展示处理进度和取消按钮，生成结果后允许试听、删除误识别音符及选择有效音区。浏览器执行模型需要额外下载、算力和内存预算，不能保证所有设备上都流畅；是否采用本地模型或服务端处理需单独评估。

### 音源与发声（建议）

原型内置一种柔和铃音合成器，覆盖旋律所需音域；不要求为每个音符单独存一个文件。踩中时按绑定音高发声，时长参考音符数据，配短起音和自然衰减。若以后要真实钢琴质感，可改用采样音源。

利用首次起跳点击创建或恢复 Web Audio 音频上下文，避免浏览器自动播放限制。[5] 单次命中应尽快发声，使用音频时钟管理停止和衰减；暂停时停止当前音并保存进度，继续后等待下一次踩星，不补播积压音符。

## 八、音乐节奏与首个曲目验证

### 实施顺序（已确定）

先把不带音乐的游戏本体做完，再加乐曲功能。首个验证曲目为内置的 `assets/canon.mid`（D 大调卡农），角色动作参考图（月面站立图 / 跳跃上升图 / 跳跃下落图）也在同一目录。

### 两个要区分的概念（术语约定）

用户口述的"识别音频的主调"拆成两个不同的问题，实现难度完全不同：

- **主旋律轨识别**：多轨 MIDI 里哪条轨是旋律。MIDI 是乐谱事件不是音频波形，不需要信号处理，用"音符数量、平均音区"等启发式规则预选即可。
- **选段**：一首曲子里哪一段适合生成阶梯。用音符密度、音域跨度、大跳频率衡量。

### 节奏对齐模式（已确定：乐句跟随制）

M4 试玩确认跳跃摘星形态与乐曲节奏存在结构性错位（弹跳节奏被物理锁死，与音符时刻对不齐），音乐模式改为"引航"形态：

- 星星 = 乐句锚点，不是一个音符一颗星。优先选乐句开头、长音、拍点上的音，相邻锚点间隔约 2–4 秒。
- 时钟跟随玩家：踩中锚点后，它到下一锚点之间的旋律与伴奏按原速自动播放；播完后全曲暂停，下一颗锚点呼吸变亮，等待玩家，多久都行。
- 等待期间安静，"音乐空白"就是迟到的代价；音乐模式无失败，曲终即结算。
- 提前碰到下一颗（当前乐句尚未播完）= 抢拍：当前乐句被打断，音乐突兀跳段，以难听作为自然惩罚。
- 呼吸灯：当前乐句播到过半，下一颗开始微亮；播完时刻最亮，等待期间缓慢呼吸。
- 主旋律轨识别（已确定）：按"音符数量、平均音区"启发式自动预选，导入后允许用户试听换轨。

### 发声分工与判定（已确定）

- **发声分工**：踩中锚点奏响锚点音，此后到下一锚点之间的所有音符（旋律 + 伴奏）按原速自动播放；踩准衔接，乐句才连贯。伴奏仍按"剔除顶声部"规则生成，与旋律同段一起走。
- **音高映射**（已确定）：全曲音域拉满屏，最低音贴左、最高音贴右。
- **perfect 判定**：踩星时刻对比当前乐句播完的应然时刻，±100 毫秒内 perfect，±300 毫秒内 good；迟到只留音乐空白不评级，提前为抢拍。
- **失败结算**（已确定）：音乐模式无失败，落地不惩罚；曲终结算显示评级、perfect 数与演奏完成度。

第八节至此全部定案，无待确定事项。

## 九、本地保存与技术边界

### 存储位置（已确定）

使用浏览器 IndexedDB。上传的 MIDI 是二进制文件、可能达 MB 级，localStorage 只能存小文本，不适用。

### 存储内容（已确定）

- 最高纪录与设置（静音、音量、减少特效等）。
- 用户上传的 MIDI 原文件。
- 解析后的音符序列（含主旋律轨选择结果）。

下次打开时音乐列表直接出现已上传曲目，不重新上传、不重新解析。

### 成绩纪录（已确定）

自由模式记一个总纪录；音乐模式每首曲子独立记录最高分与最远演奏进度，曲子之间不互相比较。

### 存储配额（已确定）

写入前先检查剩余空间；写入失败（超出配额，见资料 [6]）时弹出提示，引导用户到音乐列表自行删除旧曲目。不做自动清理，删哪首由用户决定。

### file:// 直接打开（已确定）

检测到以 file:// 协议打开时，页面顶部常驻提示「当前为本地文件模式，音乐功能不可用，请通过本地服务器或网页地址访问」。此时读取本地 MIDI 会被浏览器拦截，音乐模式不可用，游戏本体照常可玩。

### 数据迁移（已确定）

首版不做存档导出 / 导入。IndexedDB 数据绑定当前浏览器，换浏览器或换设备后纪录与已上传曲目不保留，在此明确预期。
